# Kaiwu System Web

Kaiwu 平台的管理前端：统一工作台、待办与通知、项目管理与产品前端纳管、**跨环境配置移交（三方基线对比预览）**、组织与用户、项目权限与行级数据范围、受管字典、项目作用域国际化、对象存储绑定、PLAN/ANSWER 模型路由与个人会话 Agent Dock、安全运营与审计中心。

> 这是 [Kaiwu](https://github.com/kaiwuzaidao/kaiwu) 的组成部分之一，不单独使用。
> 想先看平台整体，请从入口仓开始；那里有一条 `./kaiwu up` 的本地全链路。

技术栈固定为 `@umijs/max` + Ant Design 5 + ProComponents。

## 核心管理界面能力

- **统一工作台与待办中心**：集中展示当前成员已授权项目入口、`TodoClient` 投递的动态待办（支持逾期置顶）与站内通知。
- **项目权限中心 & 行级数据范围**：同一套模型管理 `system` 与各业务项目的成员、角色、菜单按钮权限，以及按角色配置资源级数据范围（本人 / 本部门 / 本部门及下级 / 自定义部门 / 全部）。
- **跨环境配置移交（ADR 0042）**：导出含 6 类 YAML 的全量快照移交包；在目标环境导入前可视化预览新增、变更、源端删除与角色授权差异，支持按组确认授权、逐项勾选删除并记录完整移交台账。
- **受管字典、参数与项目级国际化**：区分平台全局与项目作用域；引用式 i18n 支持项目独立维护与导出导入译文，不泄露其他项目词条。
- **对象存储与定时调度**：管理加密存储账号、项目前缀绑定与连通性探测；集中管理各项目上报 Handler 的 Cron 任务、租约与执行历史。
- **受控项目 AI 助手**：支持 `PLAN` 与 `ANSWER` 分离模型配置、个人历史会话与显式记忆、声明式补参表单，以及写操作前预览确认。
- **项目工厂 & 安全运营**：查看双仓脚手架生成与 `ADOPT_FRONTEND`（沿用已有产品前端）纳管任务；在线会话查看、强踢下线与 CLI 设备授权确认（`/device`）。

## 本地开发

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

打开 <http://127.0.0.1:8000>。

**`/api` 必须经过 8088 的 Gateway，不得直连 System 的 8080。** 直连会绕过身份校验、
在线会话和项目成员判断，本地跑通的东西到了任何真实环境都会失败。

## 容器运行

Compose 与 Kubernetes 使用同一个镜像，切换环境不需要重新构建前端——
上游地址在运行时由 `KAIWU_GATEWAY_UPSTREAM` 注入，只接受 `host:port`，不含协议和路径：

```bash
docker run --rm -p 8000:8080 \
  -e KAIWU_GATEWAY_UPSTREAM=127.0.0.1:8088 \
  kaiwu-system-web
```

## 权限与导航

左侧导航按当前用户在 `system` 项目下的权限快照过滤，不是前端写死的菜单树。

权限码在**后端注解、前端按钮、菜单 SQL 三处必须完全一致**，由 `pnpm check:perm` 校验。
新增受权限保护的功能时，菜单 seed 要一并写进增量 SQL——只在运行库里手工建菜单不算数，
全新安装会缺这条权限，管理员无法把它授予任何角色。

角色与菜单没有顶层平行入口：内置的 `system` 项目负责平台成员、系统角色、平台菜单和
登录权限；其他项目的「权限中心」负责各自的成员、角色、授权和业务菜单树。

## 前端约定

- 需要翻译或运营配置的业务状态/枚举，一律通过 `DictionaryText` 展示，未知值原样显示。
  内部状态机、协议码和只参与分支判断的枚举保留代码常量。由 `pnpm check:dict` 校验。
- 19 位 ID 在前端和 JSON 契约中保持字符串，不要交给 `number`。
- `console` 不得输出凭据或敏感个人信息，由 `pnpm check:log` 校验——
  浏览器控制台会被录屏、被监控 SDK 采集。
- `src/app.tsx` 只能导出 Umi 运行时支持的键，工具函数放独立文件。

## 验证

```bash
pnpm verify
```

一条命令覆盖类型、架构、i18n、权限、字典、日志、格式、构建、许可证与依赖审计。
提交前跑它，CI 跑的是同一条。

### 工作台受管待办深链接与项目多服务登记（默认受开关控制）

- **受管待办深链接**：子应用通过本项目配置 `workspace.deep-links` 登记白名单（JSON 路由前缀与允许的查询参数），由宿主重新校验后进入 `/workspace/{projectId}?route=...`，未登记路由或跨项目覆盖均回退至项目首页。
- **项目多服务登记面板**：开启多服务开关后，项目详情页支持查看与修改非 `default` 后端服务地址及查看对应独立 audience 的 Gateway 显式路由片段。
